SKINFORGE HELP

Your guide to making a skin

Create a skin, inspect it on a dinosaur, then export its JSON for your server. Open a topic below for details. Closing this guide keeps your work in place.

Quick start
  1. Start with the default skin or use Open JSON file to load an existing one.
  2. Choose a Species in the 3D viewer and set your skin's sex and pattern index.
  3. Edit the colour cards or press Random colours. Lock colours you want to keep while randomising.
  4. Inspect your skin from different angles and adjust Light intensity if needed.
  5. Name your skin, use Save current to keep a browser copy, and Download for a backup.
  6. Use Copy or your downloaded JSON with your server's skin-import tool. SkinForge does not apply skins to the game automatically.
Importing and editing JSON
  • Open JSON file: choose one file to edit it. Choose multiple files to add valid skins to your library and open the first valid skin.
  • Drag and drop: drop JSON files onto the Skin JSON panel to import them.
  • Paste a code: paste into Skin JSON, then press Load pasted JSON. Editing the text alone does not apply it to the editor.
  • Valid / Invalid: this checks the skin data, not whether a server will accept it. An explanation below the JSON identifies invalid fields or describes the syntax error, with a line and column when available. Fix the reported problem to check for the next one. Use valid JSON with double quotes and finite numbers.

Copy and Download export the active editor skin. Always load pasted edits first. Missing standard fields receive defaults; missing alpha values default to 1. Supplied alpha values are preserved.

Skin name, sex, variation and patterns
  • Skin name: names your download and supplies the suggested name when saving to your library. It is not a field in the exported skin JSON.
  • Male / Female: sets the JSON sex flag. Female previews replace the male-display tint with the body tint; the viewer does not switch to a separate female model or reproduce every sex-specific feature.
  • Skin variation: is exported, but its in-game effect is not simulated by the viewer.
  • Pattern index: selects an adult pattern, starting at 0. If the selected species lacks that index, the viewer shows pattern 0 and a notice. Your exported index is kept.

Species and skin stage are preview choices, not fields added to your skin JSON.

Colour cards, randomising and locks

Edit all ten layers: male display, markings, body, flank, underbelly, detail 1, eyes, teeth, mouth and claws. Which regions they affect depends on the species and pattern.

  • Click a colour swatch to use the normal colour picker, or enter exact R, G, B and A values. Normal values run from 0 to 1. Alpha (A) is editable and exported, but its in-game effects are not simulated in the 3D preview. The colour picker changes RGB only.
  • Values below 0 or above 1 receive a Glitch label. Swatches and the 3D preview clamp those values for display; exported values remain outside the normal range.
  • Both Random colours buttons randomise RGB in unlocked layers from 0 to 1 and set their A to 1. Alpha is never randomised. Locked layers retain all four values. Sex, variation and pattern index stay unchanged.
  • Random colour theme: choose Rock, Bush, Forest, Desert, Sand, Green, Jungle, Highlands, Plains, Swamp, Snow or Autumn to keep randomised colours within that palette. Any colours restores unrestricted randomisation. Both theme selectors stay in sync, and both Random colours buttons use the selection. All unlocked layers, including eyes, teeth and mouth, follow the theme; lock any you want to preserve. Changing the theme alone does not edit your skin. Your theme choice is remembered in this browser. These are creative palettes, not official game presets.
  • Lock / Locked: excludes that whole colour from randomising. Click again to unlock. If all colours are locked, randomising is disabled.
  • Locks only affect randomising. Manual edits, Glitch Lab, imports and resets can still change locked colours.
  • Reset layer: restores one colour to its starter value. Reset base: restores all starter skin values, including sex, variation and pattern index.
3D viewer and lighting controls
  • Species: selects the preview model. Unreleased species are labelled and show a notice; model-missing entries cannot be selected. Availability labels are a recorded roster snapshot.
  • Skin stage: switches adult, juvenile or hatchling textures where available. These are shown on adult geometry; the dinosaur's growth proportions do not change.
  • Orbit: drag with the left mouse button or one finger. Zoom: scroll or pinch. Pan: right-drag or move two fingers together.
  • Keyboard: focus the model with Tab or click it, then use arrow keys to orbit, + / − to zoom, or Home to reset the view.
  • Reset view: recentres the camera. Auto rotate: toggles continuous rotation.
  • Light intensity: adjusts the lights illuminating the dinosaur from 0% to 120%. At 0% the lights are off; 100% is the softer default lighting (equivalent to the previous 30%). Your first visit after this lighting update resets the setting to the new default; later adjustments are remembered. It does not change your skin colours or JSON.

The viewer is an approximation. Game lighting, materials, skin variation, growth and sex-specific features can look different. Some species lack detail masks or use a limited body-and-eye preview; read the note below the model.

Glitch Lab
  1. Choose the Target layer you want to change.
  2. Choose an Effect: positive, negative, positive blowout / bleed, negative blowout / bleed, or neutral outline. Changing the effect fills in its default values.
  3. Choose a Glitch colour. Its RGB channels receive the Active value; the remaining channels receive the Quiet value. For example, cyan activates green and blue.
  4. Adjust those numbers if desired, then press Apply to layer. Neutral outline uses −1000 for all three channels and disables the other settings.

The 3D viewer cannot show game glitch effects. Export and apply the skin using your server's tools, then view it in-game. Effect names describe experimental settings, not guaranteed results; game versions and servers can behave differently.

Saved skins, backups and exporting
  • Save current: enter a name to add a snapshot to Saved skins. Later edits do not update that snapshot automatically; save again to keep another version.
  • Click a saved skin to load it. Use its × button to delete the library entry. Undo does not restore deleted library entries.
  • Your active skin, name, saved library, colour locks, selected species and light setting are remembered in this browser when browser storage is available.
  • Local saves do not sync to other devices, browsers or site addresses. Clearing site data can remove them. Download JSON copies for backups or sharing.
  • Copy: copies the active skin JSON. Download: saves it as a JSON file using the skin name.
Undo, redo and shortcuts

The header arrows undo or redo skin edits in the current session. History is not kept after a page reload, and does not cover names, library changes, locks or viewer controls.

  • Ctrl / Cmd + Z: undo.
  • Ctrl / Cmd + Y, or Shift + Z with Ctrl / Cmd held: redo.
  • Ctrl / Cmd + S: download the active skin JSON.
  • Esc: close this guide. Tab moves between controls; Enter or Space opens guide topics.
Experimental egg generator

Open Egg generator below the viewer. Paste or import both parents' JSON, or use the current editor skin for each parent. Choose the same species in the viewer: parent JSON does not contain a species identifier.

Adjust Parent influence to explore different inheritance chances, then generate six estimated eggs. Each colour's RGB comes intact from one parent; pattern and variation are inherited together. Sex is picked at 50/50 and alpha is set to 1. These simulation rules and the influence setting are not verified game mechanics.

Each egg shows which parent supplied each colour. Preview in editor loads that egg into the main 3D viewer and JSON editor; Undo restores the previous skin. This replaces the whole skin, including locked colours. Download JSON saves an individual egg, or save a previewed egg to your library. Parents and results are temporary and disappear on reload. Growth stages still use the adult mesh.

Reporting an issue

Choose Report an issue in the header, describe the problem, and optionally attach up to three images (PNG, JPEG, GIF or WebP, up to 2 MB each). You can also include the active skin JSON; the toggle is off by default. Review the skin code before sending. Pasted edits must be loaded into the editor first.

The message, viewer species, selected images and optional skin code go to the site's Discord review channel. A confirmation appears after delivery. If sending fails, your report stays in the form so you can retry. Closing the form keeps your draft until the page reloads.

Troubleshooting
  • Colours look different in-game: check species, sex, pattern index and skin stage first. Adjust preview lighting, and remember the viewer cannot exactly reproduce the game's materials.
  • A pasted code has no effect: press Load pasted JSON and check for validation errors.
  • Randomising changes nothing: unlock at least one colour.
  • The model looks black: increase Light intensity and check whether the colour values are negative or near zero.
  • A model or texture fails to load: use Retry if offered, check your connection, or reload. Larger textures can take longer to download.
  • The viewer cannot start: use a browser with WebGL 2 and hardware acceleration available. If its graphics context is lost, reload the page.
